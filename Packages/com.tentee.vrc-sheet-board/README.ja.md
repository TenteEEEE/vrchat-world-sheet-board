# Sheet Board

Google スプレッドシートの表を、**ワールドを再アップロードせずに** VRChat ワールドの掲示板へ表示するギミックです。

イベントの当番表、ローテーション表、タイムテーブル、お知らせなどを運営チームのスプレッドシートで管理し、シートを書き換えるだけで数分以内にワールド内の掲示板にも反映されます。

- 背景色・文字色・太字・セル結合・列幅・行の高さ・配置など、シートの見た目をなるべくそのまま表示します。
- 来訪者は VRChat の設定（「信頼されていないURLを許可」）を変える必要がありません。
- 全員が同じ公開データを読むので、途中から入った人にも同じ内容が表示されます。

## 1. しくみと役割分担

```
運営のスプレッドシート
   │  シートに入れた Apps Script が、変更を見つけて自動で送る
   ▼
管理者の GitHub Gist（公開データの置き場所）
   │  VRChat が読み込める場所
   ▼
ワールドの掲示板（約 1 分ごとに読み込み）
```

VRChat のワールドは Google のサイトから直接データを読めません（VRChat が許可しているサイトに入っていないため）。そこで、VRChat が読み込める **GitHub Gist** にシートの内容を自動でコピーし、ワールドはそこを読みます。

### 役割

| 役割 | 人数 | やること | GitHub |
| --- | --- | --- | --- |
| **管理者** | 運営の中で 1 人 | シートの準備、GitHub との連携（最初に 1 回） | アカウントが必要 |
| **ワールド作者** | 1 人 | Unity で掲示板を置き、URL を設定してワールドをアップロード（最初に 1 回） | 不要 |
| **運営スタッフ** | 何人でも | シートを編集するだけ | 不要 |
| **来訪者** | — | 何もしなくてよい | 不要 |

- 管理者とワールド作者は同じ人でも構いません。
- **GitHub を使うのは管理者 1 人だけ**です。スタッフはシートの共有（編集者）を受けて書き換えるだけです。

## 2. 管理者がやること（最初に 1 回）

所要時間の目安は 15〜20 分です。

### 2-1. GitHub アカウントを用意する

[github.com](https://github.com/) で無料アカウントを作ります。個人のアカウントではなく、**Sheet Board 専用（運営チームの共用）アカウント**をおすすめします。

- 管理者が交代しても、公開先の URL を変えずに引き継げます（[7. 困ったとき](#管理者が交代するとき) 参照）。
- 公開先の URL に GitHub のユーザー名が入るため、個人のユーザー名を出さずに済みます。

### 2-2. スプレッドシートに Apps Script を入れる

> 配布者からテンプレートのシート（「コピーを作成」リンク）をもらった場合は、この手順は不要です。コピーしたシートを開けば 2-3 に進めます。

必要なファイルは `SheetBoard.gs` と `appsscript.json` の 2 つです。ワールド作者から受け取るか、Unity プロジェクトの Project ウィンドウで **Packages → Sheet Board → AppsScript** から取り出せます（パソコン上の場所は `Packages/com.tentee.vrc-sheet-board/AppsScript/`）。

`.unitypackage` で手動導入した場合は、同じファイルが **Assets → SheetBoard → AppsScript**（`Assets/SheetBoard/AppsScript/`）にあります。

1. 掲示板に出したい表のある**スプレッドシートを開きます**。
2. メニューの **拡張機能 → Apps Script** を開きます。
   - スプレッドシートに紐づいた Apps Script を開きます。
3. 最初からある `コード.gs` の中身をすべて消し、`SheetBoard.gs` の中身を貼り付けて保存します（Ctrl+S）。
4. 左の **⚙ プロジェクトの設定** を開き、「**「appsscript.json」マニフェスト ファイルをエディタで表示する**」にチェックを入れます。
5. エディタに戻ると `appsscript.json` が表示されるので、中身を配布の `appsscript.json` の中身で置き換えて保存します。
6. スプレッドシートのタブに戻り、**ページを再読み込み**します。数秒でメニューに **SheetBoard** が表示されます。

Sheet Board は、スプレッドシートに紐づいた Apps Script として動作します。

### 2-3. セットアップを実行する

1. メニューの **SheetBoard → はじめにセットアップ** を選びます。
2. 初回は Google の許可画面が出ます。
   - Google アカウントを選び、表示された確認画面で **詳細** → **（プロジェクト名）に移動** → **許可** を選びます。
3. **GitHub 連携**の画面に番号付きの手順が表示されます。
   1. 「**コードをコピー**」を押します。
   2. 「**GitHubを開く**」を押します。開いたページ（github.com/login/device）でコードを貼り付けます。
   3. **Continue** → **Authorize** を押します。
   4. スプレッドシートの画面に戻ります。承認の確認が終わるまで、この画面を閉じないでください。
   - Device Flow の期限付きトークンはスクリプトが更新し、5 分ごとの自動確認時にも期限を確認します。更新用トークンの期限切れなどで再認証が必要な場合は、**SheetBoard → 管理者用 → GitHub連携をやり直す** を選んでください。
4. 「**✔ セットアップが完了しました**」と URL の入力欄・「**コピー**」ボタンが表示されたら完了です。
   - この URL をワールド作者に渡してください。URL はあとから **SheetBoard → 状態とURLを表示** でも確認・コピーできます。
   - 掲示板に出るのは、設定タブに書いた範囲だけです。
   - 範囲がまだ無い場合は「**次にやること**」が表示されます。次の手順で表を追加してください。

この時点ではまだ表は公開されていません（中身が空の公開先が作られただけです）。

### 2-4. 掲示板に出す範囲を決める

セットアップで **SheetBoard設定** というタブが増えています。2 行目に例の行が入っています。

| 名前 | 範囲 | … |
| --- | --- | --- |
| `#sample` | `シート1!A1:F20` | … |

1. 掲示板に出したい表全体をドラッグで選択し、メニュー **SheetBoard → 選択範囲を掲示板に追加** を選びます。例の `#sample` 行が置き換わり、`board1` などの名前で追加されます。
   - 数分以内に掲示板に反映されます。掲示板が複数ある場合は、ワールド作者に名前「boardN」を伝えてください。
2. 手で書く場合は、範囲（B 列）に表の範囲を入力し、名前（A 列）の先頭の `#` を消して分かりやすい名前（例: `rotation`）にします。
3. 設定タブの **H 列「状態」** と **J 列の全体の状態** で、反映状況を確認できます。編集後は「編集の反映を待っています（数分以内に自動で公開されます）」と表示されます。

名前が `#` で始まる行は公開されません。範囲を決める前に誤って公開しないための仕組みです（一度公開した内容は履歴に残るため）。

既に使っているシートで `SheetBoard.gs` を更新した場合は、更新後に一度だけ **SheetBoard → 管理者用 → GitHub連携をやり直す** を実行してください。旧版では更新用トークンを保存していないため、同じ GitHub アカウントで連携し直して保存します。公開先の URL は変わりません。

### 2-5. 設定タブを保護し、スタッフにシートを共有する

1. **SheetBoard設定** タブを右クリック → **シートを保護** → 「権限を設定」で、編集できる人を管理者だけにします（理由は [6](#6-公開される内容と安全な運用)）。
2. スプレッドシート右上の **共有** から、運営スタッフを「編集者」として追加します。**編集者は信頼できる人だけ**にしてください。

スタッフは GitHub も Apps Script も触る必要はありません。スタッフが編集しても、自動公開は管理者のアカウントで行われます。

### メニューの使い分け

| メニュー | 使う人・動作 |
| --- | --- |
| **SheetBoard → はじめにセットアップ** | 初回セットアップは管理者が実行します。セットアップ済みのシートで管理者以外が押すと確認画面が出ます。スタッフはシートを編集するだけでかまいません。 |
| **SheetBoard → 選択範囲を掲示板に追加** | 表を選択して範囲を追加します。 |
| **SheetBoard → 今すぐ公開** | 誰でも使えます。成功時は「✔ 公開しました。ワールドの掲示板には1〜2分で反映されます。」と表示されます。管理者以外のときは「受け付けました。数分以内に自動で公開されます。操作は不要です。」と表示されます。 |
| **SheetBoard → 状態とURLを表示** | 誰でも使えます。 |
| **SheetBoard → 管理者用 → GitHub連携をやり直す** | 管理者が GitHub と再連携します。 |
| **SheetBoard → 管理者用 → 公開先を作り直す** | 管理者交代時に使います。実行前に内容を理解した確認チェックが必要です。新しい URL になるため、ワールドの再アップロードが必要です。 |
| **SheetBoard → 管理者用 → 連携を解除** | 管理者が自分の連携を解除します。 |

管理者以外がメニューを初めて使うときも、Google の許可画面（「このアプリは Google で確認されていません」）が出ます。2-3 と同じ手順で許可してください。

## 3. ワールド作者がやること（Unity）

必要なもの: Unity 2022.3、VRChat Worlds SDK 3.8 以降（UdonSharp・TextMeshPro 込み）。

> VRChat 実機での権限変更・通信・ログは未検証です。

### 3-1. パッケージを入れて掲示板を置く

1. VRChat Creator Companion（VCC）の **Settings → Packages → Add Repository** に `https://tenteeeee.github.io/vpm-repos/index.json` を追加し、プロジェクトの **Manage Project** から **Sheet Board** を追加します。
   - 手動導入する場合は、[GitHub Releases](https://github.com/TenteEEEE/vrchat-world-sheet-board/releases) の `.unitypackage` を Unity にインポートします。
2. TextMeshPro を初めて使うプロジェクトでは、Unity の **Window → TextMeshPro → Import TMP Essential Resources** を実行しておきます。
3. シーンを開いた状態で **Tools → TenteEEEE → Sheet Board → Install Sample into Current Scene** を実行します。
   - データ取得役の `SheetBoard Source` と、掲示板の `SheetBoard Display` がシーンに置かれます。
   - prefab などはビルド済みで同梱されています。ほかの準備は不要です。

### 3-2. URL を設定する

1. `SheetBoard Source` を選びます。
2. インスペクターの **ベース URL** に、管理者から受け取った URL を貼ります。
3. **URL を適用** を押します。
   - URL を入れても適用していない場合は、ビルドチェックが警告を出します。URL を適用してからアップロードしてください。
4. **接続を確認** を押します。エラー（赤）や警告（黄）ではなく、「HTTP 200 / sheetboard/1」と表示されれば成功です。
   - 結果に「範囲: …」として、設定タブの名前の一覧が表示されます（`#` で始まる行は含まれません）。
5. **ワールド内の閲覧権限** を開きます。既定の「全員」なら Controller は不要です。閲覧を制限する場合は先に対応する PermissionController を指定し、閲覧権限を選びます。Controller が無い制限付き Source は取得できず、ワールドのビルドも通りません。

### 3-3. 表示する範囲を選ぶ

`SheetBoard Display` の **範囲名** に、設定タブの「名前」列と同じ文字（例: `rotation`）を入れます。

- 「接続を確認」をした後なら、範囲名の横のリストから選べます。
- **空欄のままなら、設定タブの一番上の範囲が表示されます。** 範囲が 1 つだけなら空欄のままで構いません。

### 3-4. 位置と大きさを整える

- 掲示板は既定で幅 1.6 m × 高さ 1.0 m です。**行の多い表は文字が小さくなるので、オブジェクトを拡大**してください（20 行前後の表なら幅 3 m 程度が目安）。
- 文字だけを大きくしたいときは、Display の **文字の拡大率**（既定 1.4）を上げます。
- 文字が列からはみ出す場合は、Display の **列幅を自動調整**（既定 ON）を使います。必要幅に合わせて列幅と文字サイズが自動で決まります。
- 白地の掲示板が既定です。黒地にしたいときは `Prefabs/SheetBoard Display Dark.prefab` を使います。

### 3-5. 掲示板を増やす

`Prefabs/SheetBoard Display.prefab`（白地）または `SheetBoard Display Dark.prefab`（黒地）をシーンに置き、**データ元** に既存の `SheetBoard Source` を、**範囲名** に表示したい名前を設定します。同じ公開 URL を使う掲示板は、1 つのデータ元を共有できます。別の公開 URL も使う場合は、URL ごとに Source を追加します。

### 3-6. 動作確認とアップロード

Unity の再生（Play）でも実際の公開データを読み込みます。表が表示されることを確認してから、ワールドをアップロードしてください。

**URL を設定してアップロードした後は、シートを編集するだけで内容が変わります。** ワールドの再アップロードが必要になるのは、公開先の URL が変わったとき（[7. 困ったとき](#7-困ったとき) 参照）だけです。

## 4. 運営スタッフがやること（ふだんの更新）

**シートを編集するだけです。** 保存ボタンもありません。

- セルの値・色・太字などを変えると、数秒〜十数秒で公開されます。続けて編集した場合は、最大 5 分ほどでまとめて公開されます。
- 数式の計算結果だけが変わった場合（ほかのセルを参照している式など）も、最大 5 分ほどで反映されます。
- ワールドの掲示板は約 1 分ごとに読み込みます。掲示板右下の **更新** ボタンを押すと、自分の画面だけすぐ読み込み直せます（30 秒に 1 回まで）。

**公開されたかは設定タブの H 列・J 列で確認できます（メニューを開く必要はありません）。** H 列は範囲ごとの状態、J 列はシート全体の状態です。

| J 列の表示 | 意味 |
| --- | --- |
| ✔ 正常に公開されています | 正常に公開されています。 |
| ⏳ 編集を反映待ちです（最大5分） | 自動公開を待っています。 |
| ⚠ 自動公開が止まっているようです | 管理者がセットアップをもう一度実行してください。 |
| ⚠ 掲示板に出す範囲がありません | 範囲を追加してください。 |
| ⚠ 公開できませんでした: … | 管理者が次にやることを確認してください。 |

### 掲示板の左下の表示

時刻は、表の内容が最後に変わった時刻を、見ている人の端末の時刻で表示します。

| ランプ | 表示の例 | 意味 |
| --- | --- | --- |
| 緑 | 更新 21:05（3分前） | 正常 |
| 黄 | 更新 21:05（2時間前）・自動公開が止まっています | シートからの自動公開が 90 分以上届いていない。管理者が「状態とURLを表示」でエラーを確認してください |
| 黄 | 更新 21:05（3分前）・再試行中 | 読み込みに失敗し、前回の内容を表示したまま再試行中 |
| 赤 | 読み込み中… / 近づくと読み込みます | 入室直後・掲示板から離れている（まだ一度も読み込んでいない） |
| 赤 | 読み込めません（…）  再試行まで○秒 | 一度も読み込めていない。自動で再試行します |

### 編集時の注意

- **設定タブで指定した範囲の中身が、そのまま公開されます。** 範囲の外のセルや、指定していないタブは公開されません。
- 行や列を非表示にすると、掲示板でも表示されません。
- 掲示板に出したくないメモは、範囲の外に書いてください。

## 5. 設定タブの書き方

**SheetBoard設定** タブの 1 行が、掲示板 1 枚分の表です。

| 列 | 見出し | 書くこと | 例 |
| --- | --- | --- | --- |
| A | 名前 | ワールド側で指定する名前。英数字がおすすめ。**`#` で始めると公開されません** | `rotation` |
| B | 範囲 | 表示するセル範囲。`シート名!開始セル:終了セル` | `ローテーション表!A1:F19` |
| C | タイトル | 掲示板の上に出す見出し。空でもよい | `今週のローテーション` |
| D | 1行目は見出し | 1 行目を色の帯で強調する。シートで見出しに色を付けているなら不要 | □ |
| E | 書式を反映 | シートの色・太字・結合・列幅などを再現する | ☑ |
| F | 列幅の比 | 列幅を手で決めたいときだけ。空なら既定の自動調整で文字が収まる幅を確保し、書式を反映する場合はシートの列幅比も保ちます。自動調整は Display の「列幅を自動調整」で OFF にできます | `1,3,1` |
| G | 配置 | 列ごとの寄せを手で決めたいときだけ（`l` 左・`c` 中央・`r` 右）。空なら、書式を反映する場合はシートどおり、それ以外は左寄せ | `l,c,r` |
| H | 状態 | 範囲ごとの状態。自動で書かれます。**編集しないでください** | `✔ 掲示板に表示されます` |
| J1:J4 | 全体の状態 | シート全体の状態・次にやること・内容の更新時刻。自動で書かれます。**編集しないでください** | `✔ 正常に公開されています` |

- **範囲は表全体を囲んでください。** 例えば 6 列 × 19 行の表なら `A1:F19` です。
- シート名にクォート（`'`）は不要です（付けても動きます）。
- 範囲の末尾の空行・空列は自動で削られます。
- 掲示板を何枚かに分けたいときは、行を増やして名前を変えます（例: `rotation`、`members`）。
- 1 枚のスプレッドシートからは 1 つの URL にすべての有効な範囲を公開します。異なる閲覧権限で別の内容を出す場合は、スプレッドシートを分け、それぞれに Source と Display を用意してください。
- 一時的に公開をやめたい範囲は、名前の先頭に `#` を付けます。
- 書き間違いのある行は飛ばされ、ほかの行は公開されます。飛ばされた理由は **SheetBoard → 状態とURLを表示** の「お知らせ」に出ます。
- 列幅の比（F 列）や配置（G 列）の書き方が違う場合は、H 列に注意が表示されます。設定タブの H 列・J 列は状態表示用なので、編集しないでください。
- 範囲を追加した人が管理者でない場合、H 列に「⏳ 管理者の自動公開を待っています」と表示されることがあります。管理者の自動公開後に状態が更新されます。
- 範囲は最大 20 個、1 つの範囲は最大 100 行 × 20 列です。

## 6. 公開される内容と安全な運用

### 公開される内容

- **ワールド内の閲覧を制限する場合**: 公開した内容は、URL を知っている人なら誰でも読めます。閲覧権限はワールド内の表示と通常の取得を制限するもので、データの秘匿ではありません。ワールド作者はこの点を踏まえて設定し、閲覧権限ごとに異なる内容を出す場合はスプレッドシートを分けてください。URL や取得済みのコピーは、知っている人から隠したり失効させたりできません。
- **過去の内容も残ります。** Gist は更新のたびに履歴を残し、URL を知っている人は過去の版も見られます。シートから消しても、以前に公開した内容は履歴に残ります。
- 公開先の URL には **GitHub のユーザー名**が、Gist の説明には**スプレッドシートの名前**が入ります。
- **本名・連絡先・非公開の予定など、見られて困る情報は、最初から範囲に入れないでください。**

### シートの編集者について

スプレッドシートの編集者は、設定タブを書き換えて別のタブを公開したり、Apps Script を書き換えたりできます。Apps Script は管理者の GitHub 連携で動いているので、悪意のある編集者は管理者の GitHub に手を出せてしまいます。

- **編集者は信頼できる人だけ**にしてください。
- **設定タブを保護**して、管理者だけが編集できるようにしてください（[2-5](#2-5-設定タブを保護しスタッフにシートを共有する)）。
- GitHub は **Sheet Board 専用のアカウント**を使ってください。万一のときも、ほかのリポジトリに影響しません。

### 誤って公開してしまったとき

管理者が GitHub の Gist のページでその Gist を削除してください（履歴ごと消えます）。次の公開時に新しい公開先が作られますが、**URL が変わるので、ワールド作者に URL の差し替えと再アップロードを依頼**してください。新しい URL はメールと「状態とURLを表示」で知らされます。

## 7. 困ったとき

### セットアップ中のエラー

| 表示 | 原因と対処 |
| --- | --- |
| 「SheetBoard」メニューが出ない | シートを再読み込みしてください。それでも出ない場合、スクリプトがシートに紐づいていません（script.google.com で別に作った等）。[2-2](#2-2-スプレッドシートに-apps-script-を入れる) の手順で、シートの「拡張機能 → Apps Script」から入れ直してください |
| 「コードの有効期限（15分）が切れました」 | この画面を閉じて、同じメニューをもう一度実行してください |
| GitHub連携の有効期限切れ・再認証が必要という案内 | **SheetBoard → 管理者用 → GitHub連携をやり直す** を実行してください。同じ GitHub アカウントなら URL は変わりません。 |
| 「GitHubで承認がキャンセルされました」 | この画面を閉じて、同じメニューをもう一度実行してください |
| 「この公開先は○○さんのGitHubにあります」 | 別の人の GitHub で作られた公開先です。管理者以外がセットアップを実行した場合や、管理者の交代で起きます。[管理者が交代するとき](#管理者が交代するとき) を参照 |
| 「引数が無効です: timeZone」「「名前」の範囲を確認してください」 | 古い版のスクリプトです。最新の `SheetBoard.gs` を貼り直してください |

### 設定タブの「お知らせ」（状態とURLを表示）

| 表示 | 原因と対処 |
| --- | --- |
| `⚠ シート「X」が見つかりません。タブ名を確認してください` | 範囲のシート名が実際のタブ名と違います。タブ名をコピーして貼り付けてください。 |
| `⚠ 範囲「A1:F19」を読めません。` | 範囲のセル番地の書き方を確認してください。 |
| `⚠ 同じ名前が上の行にあるため使われません` | 同じ名前の行が複数あります。上の行だけが使われます。 |
| `⚠ 名前（A列）が空のため公開されません` | A 列に範囲名を入力してください。 |
| `⚠ 範囲は20個までのため省きました` | 公開する範囲を 20 個以内にしてください。 |
| `⚠ 範囲に文字が入っていません` | B 列の範囲と、範囲内の内容を確認してください。 |
| `✔ 掲示板に表示されます ／ …` | 範囲は表示されます。続く注意の内容を確認してください。 |

### 掲示板の表示

| 表示 | 原因と対処 |
| --- | --- |
| 範囲「xxx」が見つかりません | 範囲名が設定タブの「名前」と一致していません（大文字・小文字も区別します）。名前の先頭が `#` の行は公開されません |
| 何も表示されない（タイトルも空） | まだ一度も読み込めていません。左下の表示を確認してください |
| URLが設定されていません | Source の **ベース URL** を入れて **URL を適用** を押してください |
| 赤ランプ「読み込めません」 | Source の **接続を確認** で原因を確認してください |
| 黄ランプ「自動公開が止まっています」 | 管理者がシートの **SheetBoard → 状態とURLを表示** で「直近のエラー」を確認してください |
| 表の一部しか出ない | 設定タブの範囲が表全体を囲んでいるか確認してください。Display の **最大行数**（既定 40）・**最大列数**（既定 12）も確認してください |
| 文字が小さい | 掲示板のオブジェクトを拡大するか、**文字の拡大率** を上げてください |
| □ と表示される文字がある | 絵文字や一部の記号はフォントに含まれません（[8](#8-再現できないもの制限) 参照） |

### 公開が止まったとき

- 公開に失敗すると、管理者のメールアドレスに「**SheetBoard: 掲示板の公開が止まっています**」という件名でメールが届きます（同じ種類のエラーは 1 日 1 回まで）。本文には何が起きたか、番号付きの手順、スプレッドシートの URL が記載されます。
- 「（エラー番号 401）」を含むお知らせは、GitHub連携の期限切れです。「GitHub連携の期限が切れたため、公開が止まっています。管理者がメニュー「SheetBoard → 管理者用 → GitHub連携をやり直す」を実行してください（URLは変わりません）。」と案内されます。
- 「（エラー番号 403）」を含むお知らせは、「GitHubで公開する許可がありません。管理者がメニュー「SheetBoard → 管理者用 → GitHub連携をやり直す」で、もう一度承認してください」と案内されます。

### 管理者が交代するとき

自動公開は、セットアップした人の Google アカウントと GitHub 連携で動いています。

- **Sheet Board 専用の GitHub アカウントを使っている場合**（おすすめ）
  1. 元の管理者が **SheetBoard → 管理者用 → 連携を解除** を実行します（元の管理者の自動公開が止まります）。
  2. 新しい管理者がシートの編集者になり、**SheetBoard → はじめにセットアップ** を実行して、同じ専用アカウントで連携します。
  3. 同じ公開先を使い続けるので、URL は変わりません。
- **元の管理者の個人 GitHub を使っていた場合**
  新しい管理者のアカウントでは元の公開先を更新できません（「この公開先は○○さんのGitHubにあります」と表示されます）。
  1. 元の管理者が **SheetBoard → 管理者用 → 連携を解除** を実行します。
  2. 新しい管理者が **SheetBoard → 管理者用 → 公開先を作り直す** を実行します。GitHub 連携の画面が出た場合は、自分のアカウントで承認した後、このメニューをもう一度実行してください。「この公開先は○○さんのGitHubにあります」と出ても、連携情報は保存されています。確認画面で内容を理解したチェックを入れて作り直すと、新しい公開先が自分の GitHub に作られ、自動公開が有効になり、新しい URL が表示されます。
  3. URL が変わるので、ワールド作者に URL の差し替えと再アップロードを依頼してください。元の公開先は元の管理者の GitHub に残るので、不要なら元の管理者が削除してください。

## 8. 再現できないもの・制限

**シートの見た目のうち、再現できないもの**

- 条件付き書式の色（Google が取得手段を提供していないため）
- 罫線（代わりに薄い格子線を表示します。Display の「格子を表示」で切り替え）
- 画像・グラフ・図形
- 絵文字や一部の記号（□ と表示されます）
- フォントの種類（すべて Noto Sans JP になります）
- セル内の縦位置（中央に固定）
- プルダウンの ▼ 印（値の文字だけ表示）。チェックボックスは ■ / □ で表示します

**制限**

- 範囲は最大 20 個、1 つの範囲は最大 100 行 × 20 列、セル 1 つは 200 文字まで。掲示板 1 枚の表示は既定で 40 行 × 12 列まで。
- Google の無料アカウントでは、Apps Script の自動実行は 1 日合計 90 分までです。Sheet Board は「編集時・書式変更時・5 分ごと」に変化を確認し、変化があるとき（と 1 時間に 1 回の生存通知）だけ送信します。範囲が非常に大きい・数が多い場合の実行時間は未計測です。止まった場合は、メールと掲示板の「自動公開が止まっています」表示で分かります。

## 9. 配布者向けの情報

### GitHub 連携（コード入力方式）について

`SheetBoard.gs` 冒頭の `GITHUB_CLIENT_ID` には、Sheet Board の OAuth App の Client ID が設定済みです。これは公開情報で、秘密ではありません。フォークして独自に配布する場合は、自分で OAuth App を作って置き換えられます。

1. GitHub の **Settings → Developer settings → OAuth Apps → New OAuth App**。
2. Application name は承認画面にそのまま出るので、分かりやすい名前にします（例: `Sheet Board (VRChat)`）。Homepage URL と Callback URL は配布ページの URL で構いません（Callback URL は使われません）。
3. 作成後に **Enable Device Flow** にチェックを入れます。
4. **Client ID** を `GITHUB_CLIENT_ID` に貼ります。**Client secret は作らない・書かないでください**（スクリプトはシートごと誰でも読めるため）。

`GITHUB_CLIENT_ID` を空にすると、コード入力の代わりに「Personal access token（classic、gist 権限のみ）を貼り付ける」方式になります。

### テンプレートシートを配る

スクリプト入りのシートを作り、共有リンクの末尾の `/edit…` を `/copy` に変えたリンクを配ると、受け取った人は「コピーを作成」を押すだけでスクリプト付きのシートを手に入れられます（2-2 の手順が不要になります）。テンプレートは「はじめにセットアップ」を実行する前の状態で配ってください。

### 仕様

設計と JSON 形式は `docs/SPEC.md` にあります。
